# v0.1 Spec

## Product Position

Agent Postmortem Kit is a local-first CLI and static HTML report generator for AI coding-agent sessions.

It should not start as a SaaS dashboard or a general observability product. The v0.1 job is to help a human answer:

- What did the agent try to do?
- Where did it fail or drift?
- What risky action appeared in the log?
- What evidence supports the final answer?
- What should be changed before the next run?
- Is there a reusable skill or operating rule hiding in this failure?

## Inputs

v0.1 accepts:

- Generic JSONL logs
- Generic JSON objects
- Plain text logs
- Markdown transcripts

Near-term adapters:

- OpenClaw session logs
- Hermes agent logs
- Codex session exports
- Claude Code JSONL logs
- AgentTrace JSON exports

## Detectors

v0.1 includes heuristic detectors for:

1. Dangerous commands
   - Examples: `rm -rf`, `git reset --hard`, `curl | sh`, `sudo`, recursive PowerShell deletes.
2. Secret exposure risk
   - Examples: OpenAI keys, GitHub tokens, AWS access keys, Slack tokens, Google API keys, suspicious env assignments.
3. Repeated failures
   - Repeated error-like events grouped by normalized message.
4. Evidence gaps
   - Explicit "not tested", "could not verify", "assuming", or similar statements.
5. Unfinished work
   - TODOs, blockers, unresolved failures, missing artifacts.
6. Human approval points
   - Dangerous operations and explicit approval/confirmation language.

## Outputs

v0.1 produces:

- Static HTML report
- Structured JSON report
- Console summary

The report must contain:

```text
Goal:
Completed:
Failed:
Risk:
Evidence:
Next action:
Human approval required:
Skill candidate:
```

## Non-Goals

v0.1 will not:

- Upload logs to an external service
- Call an LLM by default
- Call Oracle or any other outside model by default
- Modify source repositories
- Execute commands found in logs
- Replace AgentTrace's TUI, timing, cost, and token analytics
- Claim a finding is definitive without evidence

## OpenClaw Plan

OpenClaw support should be added after collecting representative local logs.

The adapter should map OpenClaw records into the common event model:

- timestamp
- role or actor
- event type
- message content
- tool name
- command text when present
- source path and line

OpenClaw-specific rules should stay separate from generic detectors unless they generalize cleanly.

## Report Severity

Severity levels:

- `critical`: likely secret exposure or destructive action with strong evidence.
- `high`: dangerous command, approval bypass, repeated hard failure.
- `medium`: evidence gap, incomplete task, unresolved blocker.
- `low`: weak signal or postmortem improvement candidate.

## Success Criteria

The v0.1 scaffold is useful when:

- A user can run one command on a copied log file.
- The generated report links findings back to file and line.
- The output highlights at least dangerous commands, secret risks, and verification gaps.
- Adding a new parser does not require changing detector logic.

## Future: Oracle Consultation

Oracle can become an optional second-opinion path when an agent is stuck. The first step should be local-only bundle generation, not API or browser execution. See `docs/oracle-consultation-plan.md`.
